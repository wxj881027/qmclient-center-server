# 2026-10-08 服务接入说明

状态：实现完成，未运行测试，未部署。

中心服务新增两个 HTTP 入口和一个可选实时事件。将 `deploy/nginx/qmclient-assistance.conf` 的内容加入现有 `qmclient.icu` 的 HTTPS server 块；其中的本地端口沿用中心服务的 8080。原有 `/ws` 接线继续复用。

- `GET /ddnet/15/servers.json`：启动后同步官方 master，此后每 60 秒同步一次。源请求最多等待 5 秒，失败尝试下一源。保留最近成功内容；超过 300 秒返回 503，客户端继续选择其他源。响应包含 Age、X-Qm-Last-Success、X-Qm-Stale，不能由代理重新缓存。
- `POST /api/v1/translate`：请求只包含 text、source、target。固定 DeepL → MyMemory，每次最多请求两个不同服务，每个最多 5 秒，整条链最多 10 秒。断开 HTTP 连接会取消请求，并停止启动后备服务。明确的结构化内容拒绝不会回退；失败只返回稳定错误类别。
- `/ws` 的 `decorative_throw`：hello 需要声明 `decorative_throw_v1`。事件携带 projectile、player_id、server_address、session_id、origin、direction。服务按当前连接的 presence 校验玩家与会话，身份字段取自 presence；只转发给同服且声明能力的连接。主号和分身共享每秒一次限制。该身份校验依赖现有 presence，不是游戏服务器认证。

维护者凭据只由部署环境提供：DEEPL_API_KEY、MYMEMORY_EMAIL，或 TRANSLATE_PROVIDERS_JSON。不要写入客户端配置、仓库或日志。

可用以下配置结构设置每个服务和每把凭据的字符预算、并发、冷却。示例中的额度用于说明字段，部署前按实际账户预算调整；0 表示不设本地字符上限，仍受上游服务额度约束。

```json
[
  {"name":"deepl","character_limit":0,"concurrency":2,"quota_window_ms":86400000,"cooldown_ms":60000,"credentials":[{"key":"<deployment secret>","character_limit":0,"concurrency":2}]},
  {"name":"mymemory","character_limit":0,"concurrency":1,"quota_window_ms":86400000,"cooldown_ms":60000,"credentials":[{"email":"<maintainer contact>","character_limit":0}]}
]
```

预算状态在本进程中维护，重启会重置；它用于控制本服务发起的请求，不替代上游账户的累计账单与账户配额。DeepL 成功响应中的 billed_characters 用于校正预留额度；无法确认是否计费的失败保留预留量。认证失败停用对应凭据到进程重启，额度错误冷却到配置窗口结束，其他临时失败使用 cooldown_ms。

客户端可手动选择“自动（Qm 服务）”，现有个人后端及默认值保持不变。部署完成、凭据可用并通过端到端验收后，再按实施计划考虑调整全新配置的默认后端。
