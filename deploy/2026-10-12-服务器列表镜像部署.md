| 地址 | 当前用途 | 服务端缓存策略 |
| --- | --- | --- |
| `https://ddrace.cn/ddnet/15/servers.json` | 当前默认第二层镜像，官方失败或预算耗尽后使用 | ddnet2 试镜像；共享快照、gzip、ETag；`public, max-age=60, must-revalidate`；超龄或忙时 503，忙时附 `Retry-After: 60` |

两套镜像各自同步官方列表；现有源码与部署记录没有建立二者串联的客户端回退关系。当前分层行为与客户端的[服务器列表获取与故障恢复规格](https://github.com/wxj881027/QmClient/blob/master/docs/规格/2026-10-11-服务器列表获取与故障恢复.md)一致，本次修正文档，不替换或新增默认来源。两处入口均可访问不等于应同时接入默认链，也不能据此认定有意保留了“双默认镜像”策略。

当前客户端同层最多两个 GET 并发，首份有效新鲜列表完成本轮；默认每层预算 30 秒，失败依次进入后层。记住的最佳地址只影响同层次序。有效非空 `ddnet-serverlist-urls.cfg` 替换整个默认集合，使用 120 秒单层预算；在该文件里加入本文地址不会自动保留官方、ddrace.cn 或 GitHub，也不会创建新的镜像优先层。

客户端独立维护最近成功列表，使用 Age/Date/Last-Modified 与驻留时间判断年龄；仅有 Age 也可识别新鲜度。失败和更旧响应不覆盖更鲜列表，持久缓存上限 8 MiB 正文、24 小时并绑定来源集合，重启显示缓存时标为待实时刷新。镜像的 HTTP 缓存头与客户端这份恢复缓存用途不同；不能把 `no-store` 解读为客户端没有恢复缓存。GitHub 备用还必须包含 `qm_snapshot_updated_at`。

## 独立部署

`serverlist_mirror_server.js` 复用 `serverlist_mirror.js` 与 `outbound_json.js`，使用中心服务已有的 Express 依赖，在 `127.0.0.1:8081` 提供镜像。独立 systemd 服务不需要重启中心服务或语音服务。

同步策略沿用现有实现：启动时同步，此后每 60 秒刷新；每个官方源最多等待 5 秒，失败尝试下一源。只发布完整、非空列表。失败保留最近成功缓存，源 Age 与本地经过时间合计超过 300 秒后返回 503，供客户端换源。GET 与 HEAD 返回 Age、X-Qm-Last-Success、X-Qm-Stale；禁止代理缓存。

1. 将三个 JS 文件复制到现有中心服务目录。本文配置使用 `/home/ubuntu/Q1menG_Client/tclient_scripts/qmclient_center_server`；其他目录需要调整 unit 的 WorkingDirectory 和 ExecStart。
2. 安装 `deploy/systemd/qmclient-serverlist-mirror.service`，执行 `systemctl daemon-reload` 与 `systemctl enable --now qmclient-serverlist-mirror`。
3. 确认本地 `http://127.0.0.1:8081/ddnet/15/servers.json` 返回有效 JSON 后，安装 `deploy/nginx/qmclient-serverlist-mirror.conf`，在 `qmclient.icu` 的 HTTPS server 内 include。
4. 执行 `nginx -t`，成功后 reload Nginx。该片段与原 `qmclient-assistance.conf` 中的镜像 location 二选一；这里只接入服务器列表镜像。
5. 检查公网 GET、HEAD 的状态、Content-Type、Age 与列表条数，并在下一个同步周期确认 X-Qm-Last-Success 更新。

回滚时，先移除新增的 Nginx include，检查配置并 reload；再停止并禁用 `qmclient-serverlist-mirror.service`。安装前保留配置备份，不覆盖中心服务其他文件或部署中的业务数据。
